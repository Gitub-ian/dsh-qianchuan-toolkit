# 千川工具箱（DSH 插件）

一个插件带两个技能：`qianchuan-live-control`（直播盯盘 + 一键控量）和 `qianchuan-plan-copy`（乘方计划复制）。

## 它解决的问题

千川把「今天花了多少、净成交多少」按**按抖音号**给你，但那是当日累计值。等肉眼从累计 ROI 里看出不对劲时，通常已经多花了半小时的钱。平台自带的补救手段是「一键调速 → 一键控量」：给这个抖音号设一个「接下来 0.5 小时最多花 X 元」的封顶。

这个插件把「人盯着看、手动控」变成「按自然小时固定节点读数据、命中规则自动控、控完回读日志核对」。

## 数据从哪来

两个来源，都不需要额外报表页：

1. **分时接口**（页面同源 fetch）：`POST /ad/api/data/v1/common/statQuery`，维度 `[stat_time_hour, ad_id]`，数据集 `site_promotion_post_overview`，一次拿当天每小时每个计划的消耗 / 净成交金额 / 净成交订单 / ROI。200–400 ms。
2. **列表行**：抖音号名称、投放状态、每日预算、ROI 目标，以及「调控工具」列上是否已有控量在跑。

接口只给 `ad_id`，不给抖音号；`aweme_id`/`plan_id` 维度会报错。所以抖音号与 ad 的映射来自计划详情页页头（「计划ID / 抖音号ID / 抖音号」），首次抓到后缓存到 `ad-map-<账户ID>.json`。

## 判定

每个自然小时的 :15 / :30 / :45 / :55 各跑一次；`:55` 读刚结束的那个小时。命中顺序：备用账号 → 找不到行 → 已有控量 → 未投放 → 无 ad → 本小时没消耗 → 跨账号歧义 → ROI 低于阈值（控）→ 其余跳过。

「消耗为 0 不控」是硬规则；更进一步，本小时消耗**未超过 `minCost`（默认 200 元，等于 200 也不控）**时同样跳过——花得少的时候控量只会白占一次控量窗口，还可能给空跑计划追加预算。

## 执行与核对

提交走真实鼠标点击（弹窗会随调控方式改变高度，所以提交前当场重新量按钮坐标）。提交后：

1. 弹窗消失；
2. 列表行出现「控量运行中」图标；
3. 计划详情页「日志」里出现「新建 / 一键控量」，且预算、时长 0.5、开始时间（与提交时刻差 ≤120 秒）与本次提交一致。

三条都过才算成功；任何一条不确定都只记录并告警，不重试。

## 多账号

一个账号一个标签页，按需创建、常驻复用（切账号 9–10 秒，复用几十毫秒）。全域投放与乘方两条产品线的表头不同（乘方多「营销服务」「投放类型」两列，且表头被复制成一行 `tr`），脚本按表头名定位列，不写死索引。

同一个抖音号同时挂在两个账号时：只有 1 个在投放就控那一个；两个都在投放则告警等人工指定（或用 `targets.mjs standby` 标记谁是备用）。

## 通知

默认不打扰。可选通道：企业微信/飞书/钉钉机器人、Server酱、PushPlus、Bark、QQ 官方机器人、OneBot（NapCat）。只推异常事件。

## 风险与边界

- 需要本机浏览器以调试端口运行并保持登录；登录态失效时只会告警。
- 一键控量的时长由平台固定为 0.5 小时，插件不尝试修改。
- 插件不做人为限流；防重复依赖平台自身的「同一时间只能有一个控量」约束。
