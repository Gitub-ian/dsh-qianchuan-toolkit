# 规则口径

## 1. 判定对象：自然小时

判定用的是**分时报表里「当前这个自然小时」**的消耗与净成交，不做差量、不做滑动窗口。

```
这个小时的消耗   = statQuery(Dimensions=[stat_time_hour, ad_id]) 里 hour = 当前小时 的 stat_cost 之和
这个小时的净成交 = total_order_settle_amount_for_roi2_1h 之和
净成交 ROI       = 净成交 ÷ 消耗
```

节点是每个自然小时的 **:15 / :30 / :45 / :55**。`:55` 那次读的是**刚结束的那个小时**（比如 09:55 读 09 点整点的完整数据），不是 09:55 这一刻的实时值。

## 2. 为什么放弃了差量法（历史沿革）

第一版是「累计值两次快照相减」：每 15 分钟抓一次列表的累计消耗/净成交，用 `t` 与 `t-30min` 相减得到「近半小时」口径，触发条件为「半小时消耗 > 300 且 ROI < 2.40」。

废弃原因（都是实践里撞出来的）：

1. **第一轮永远没有结论**：账本冷启动，至少要攒 30 分钟才开始判断，开播头半小时跑飞了抓不住。
2. **口径会漂**：页面累计值刷新有延迟，退款回冲还会让差量变负；同一时刻两次读，能差出几十块。
3. **节点与窗口不对齐**：15 分钟一跑，窗口是「最近 30 分钟」，永远对不上用户嘴里的「8 点这个小时」。
4. **拿不到实时性**：想判断「这个小时已经花了多少」，差量法要求两次采样，而分时接口一次就给了。

现在保留差量法的只有一处历史说明，代码里已无实现。用户口径也明确过：**只看净成交 ROI，消耗只作为「有没有真的在花钱」的前置条件**——消耗为 0 时控量没有意义（只是给没跑起来的计划追加预算）。

## 3. 判定顺序（hourly.mjs 实际执行顺序）

按顺序命中即停：

| 顺序 | 条件 | 结果 | 是否通知 |
|---|---|---|---|
| 1 | 目标被标为 `standby`（同账号同名的另一个账号才是主力） | skip `standby` | 否 |
| 2 | 列表里找不到这个抖音号 | skip `row-not-found` | 否 |
| 3 | 该行已有控量在跑（`iconPauseFilled`） | skip `controlling`，记 `endAt` 并加插一轮 | 否 |
| 4 | 该行不在投放中（已暂停/未开播） | skip `not-live` | 否 |
| 5 | 该抖音号没有 ad_id（映射缺失且没抓到） | skip `no-ads` | 否 |
| 6 | 本小时没有任何 ad 的消耗行 | skip `no-spend` | 否 |
| 7 | 同名抖音号跨账号同时「投放中」 | skip `ambiguous` | **是** |
| 8 | 净成交 ROI < `roiFloor`（默认 2.40） | **control**（预算 `budget`） | 失败才通知 |
| 9 | 其余 | skip `roi-ok` | 否 |

`minCost`（默认 1 元）是第 6 步的补充门槛：本小时消耗低于它同样视为「还没花钱」。

## 4. 三层覆盖

`targets.json` 里同一组字段可以在三个层级被覆盖，后者覆盖前者：

```
defaults.hourly  →  accounts[].rules.hourly  →  targets[].rules.hourly
```

可覆盖字段：`nodes` / `roiFloor` / `minCost` / `budget` / `controlHours`。

典型用法：

- 某个号客单价特别高，ROI 地板放到 1.8：`targets.mjs add --roi 1.8`
- 某个账号整体激进一点：在 `targets.json` 里给那个 account 加 `rules.hourly.budget = 500`
- 某个号只在 :20 和 :50 检查：`targets.mjs add --nodes 20,50`

## 5. 「控量」到底是什么

- 一键控量是**未来 0.5 小时内该抖音号的消耗封顶**，不是暂停，也不是降预算。封顶用完自然停跑，0.5 小时后自动解除。
- **时长固定 0.5 小时**，弹窗里改不了（平台限制）。
- **同一直播间同时只能有一个控量任务**：已有在跑的就不会出现「+」入口，这是唯一的闸门，技能不额外做冷却。
- 因此「同一小时控两次」是合法的：09:10 控了一次跑到 09:40 结束，09:45 数据仍差就可以再控一次。
- 控量中的结束时间取「上次提交时刻 + 30 分钟」，用于在结束后 1 分钟加插一轮（固定节点不取消）。

## 6. 未开播/暂停的号

已暂停或「直播间未开播」的号不控：控量对不跑量的计划没有意义。开播后平台会自动恢复投放，那时列表行变成「投放中」，下一轮自然接管。
