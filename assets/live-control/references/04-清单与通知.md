# 监控清单与通知（v8）

## 1. 数据目录与配置分层

脚本自己的东西（清单、埋点、通知配置）都放在**数据目录**里，和插件代码分开：

| 项 | 值 |
|---|---|
| 默认目录 | `~/.qianchuan-cruise`（Windows：`%USERPROFILE%\.qianchuan-cruise`） |
| 覆盖方式 | 环境变量 `QC_HOME`（开发/多开时用） |
| 清单文件 | `targets.json` |
| 埋点 | `rounds.jsonl`（每轮）、`actions.jsonl`（每笔控量）、`errors.jsonl`、`notifications.jsonl` |
| 缓存 | `ad-map-<aavid>.json`（计划 ID → 抖音号，省掉重复跳详情页） |

`targets.json` 首次运行会自动从插件自带的 `config.rules.json` 生成一份种子（只有账号和抖音号，不含历史）。

## 2. 主键是「账号 × 抖音号」，不是计划

千川的一键控量挂在**列表行**上，粒度为「账号 × 抖音号」：一个抖音号下的所有在投计划会一起被控。
所以清单的主键是 `账号key/抖音号uniqueId`（例如 `A/abc123`），计划 ID 只用于两件事：详情页核对、按 ad_id 聚合分时数据。

```json
{
  "version": 1,
  "defaults": { "hourly": { "nodes": [15,30,45,55], "roiFloor": 2.4, "minCost": 1, "budget": 200, "controlHours": 0.5 } },
  "accounts": [
    { "key": "A", "aavid": "1860000000000001", "name": "我的全域账户", "entry": "uniprom" },
    { "key": "B", "aavid": "1860000000000002", "name": "我的乘方账户", "entry": "square" }
  ],
  "targets": [
    { "id": "A/<uniqueId>", "account": "A", "awemeName": "某个抖音号", "awemeUniqueId": "abc123",
      "ads": ["1860000000000003"], "rules": {}, "enabled": true }
  ]
}
```

- `entry`：`uniprom` = 全域投放-推直播间；`square` = 乘方-推直播。两套界面表头不同，脚本按表头自动识别。
- `ads`：该抖音号下已知的计划 ID。留空则脚本会去详情页反查（慢，第一次约 3 s/个），查到后写进 `ad-map`。
- `rules`：可选，覆盖默认值。

### 2.1 同名抖音号在多个账号怎么办

一个抖音号可能同时出现在「全域投放」和「乘方」两个账户里（同一个抖音号在 A 账号投全域、在 B 账号投乘方）。脚本每轮会做判别：

| 情形 | 行为 |
|---|---|
| 只有 0 个在投放（都暂停/未开播） | 全部 `skip not-live`，不控 |
| 只有 1 个在投放（列表行是「投放中/有效投放中」） | **只控那一个**，日志里打印「同名抖音号存在于 A/B，仅 X 在投放」 |
| 2 个及以上同时投放 | 全部跳过并发 `ambiguous-aweme` 异常通知，等人工指定 |

判别依据是列表行的投放状态（不是消耗，因为小时初消耗可能还是 0）。

如果平台状态看不出来（比如两个都是「未开播」，但其中一个开播后会自动开投），用**人工指定**：

```bash
node scripts/targets.mjs standby A/shesiyahufu7    # 标为备用：这个账号不控
node scripts/targets.mjs primary A/shesiyahufu7    # 改回主力
```

标了 `standby` 的目标在 `list` 里 role=备用，每轮只读数据、判定一律 `skip standby`，并会打印「实际由 B(乘方) 投放」。
人工指定的优先级高于自动判别：同名抖音号只要有一个主力、其余备用，就只控主力。

### 2.2 一账号一标签页（不来回切账号）

多账号巡航**不需要在同一个标签页里切账号**：脚本给每个账号开一个独立标签页，互相不打扰。

- 首次运行：找 URL 里带 `aavid=<该账号>` 且停在列表页的标签页；没有就用 CDP `Target.createTarget`（后台标签，不抢焦点）新建一个。
- 之后每轮：按 URL 里的 aavid 复用同一个标签页（本轮内还做了内存缓存 + `ping()` 探活，标签页卡死会自动重开）。
- 账号之间**完全并行**，互不影响；A 的标签页停在 A 的列表，B 的停在 B 的列表，脚本只断 WebSocket，标签页一直留着。
- 实测：2 账号 3 目标，首次 10.7s（要开新标签、等图标渲染），稳态 **1.6s/轮**。

代价是浏览器里会常驻 N 个千川标签页（一个账号一个），关掉就相当于不监控那个账号——这正是「10 个抖音号 10 个标签」的做法。

## 3. 三层覆盖

```
targets[].rules.hourly  >  accounts[].rules.hourly  >  defaults.hourly
```

可覆盖字段：`nodes`（判定的分钟节点）、`roiFloor`（净成交 ROI 低于它就控）、`minCost`（消耗低于它不控）、`budget`（控量预算）、`controlHours`。
例：只想给某个抖音号设 ROI 2.0、预算 300 → 在它的 `rules.hourly` 里写 `{"roiFloor":2,"budget":300}`。

## 4. CLI

```bash
node scripts/targets.mjs list                  # 看清单
node scripts/targets.mjs accounts              # 看账号
node scripts/targets.mjs add --account A --name "某个抖音号" --uid abc123 --ads 1860000000000003
node scripts/targets.mjs add --account A --name xxx --roi 2.0 --budget 300   # 顺带给这个号单独设规则
node scripts/targets.mjs on  A/abc123         # 启用
node scripts/targets.mjs off A/abc123         # 停用（保留配置）
node scripts/targets.mjs rm  A/abc123         # 删除
node scripts/targets.mjs doctor                # 自检：目录、通知、账号、目标、生效规则
```

`doctor` 是最快的排障入口，先看它。

## 5. 通知（**可选功能**）

通知不是必需的：没有 `notify.json`、或所有通道都 `enabled:false`，巡航和控量**照常执行**，只是不推送（仍会写本地 `notifications.jsonl`）。

### 5.1 配置

把 `docs/notify.sample.json` 复制到数据目录改名 `notify.json`，按需打开通道：

```json
{
  "channels": [
    { "name": "QQ-官方机器人", "type": "qq", "enabled": true,
      "appId": "你的AppID", "clientSecret": "你的AppSecret",
      "openid": "私聊你的openid", "sandbox": false },
    { "name": "企业微信-群机器人", "type": "wecom", "enabled": true,
      "url": "https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=xxxx" }
  ]
}
```

通道按顺序**全部发送**（配两个就两个都收），任一成功即算送达；全失败写 `pending-notify.jsonl` 等下次补发，**绝不阻塞控量**。

### 5.2 支持的通道

| type | 说明 | 必填 |
|---|---|---|
| `qq` | QQ 官方机器人（仅能回复主动找过机器人的用户/群） | appId、clientSecret、openid 或 groupOpenid |
| `onebot` | OneBot v11（NapCat / LLOneBot），可发给任意 QQ 号/群 | url（默认 127.0.0.1:3000）、qq 或 groupId |
| `wecom` | 企业微信群机器人 | url |
| `feishu` / `dingtalk` | 飞书 / 钉钉群机器人 | url |
| `serverchan` / `pushplus` | 微信扫码收消息 | url |
| `bark` | iOS Bark | url |
| `json` | 任意 HTTP POST，body 为 `{title,text,level}` | url |

### 5.3 自检

```bash
node scripts/notify.mjs --test                 # 给所有启用通道各发一条
node scripts/notify.mjs --title "标题" --text "内容"
```

退出码 0 = 至少一个通道送达，1 = 全部失败（具体每个通道的 ok/status 会打出来）。

### 5.4 什么时候会发：**只报异常**

正常跑（按规则控量、轮空、ROI 达标、没开播）**一律不推送**，避免刷屏。只有这些情况发：

| 事件 | 说明 | 去重 |
|---|---|---|
| `control-fail` | 该控但没提交成功（找不到行/按钮禁用/点空/被弹窗挡） | 30 分钟 |
| `log-mismatch` | 提交成功但日志核对不上（预算/时长/开始时间不符，或没有日志行） | 30 分钟 |
| `account-fail` | 切账号或进入口反复失败，本轮没能提交 | 30 分钟 |
| `gather-fail` | 读列表/查分时数据超时，整轮抓取失败 | 30 分钟 |
| `ambiguous-aweme` | 同名抖音号在多个账号**同时投放**，无法判断该控谁 | 6 小时 |

去重记录写在数据目录 `.alerts.json`，所以连续几轮同一个故障只提醒一次。所有异常同时也写进 `errors.jsonl` / `actions.jsonl`。
