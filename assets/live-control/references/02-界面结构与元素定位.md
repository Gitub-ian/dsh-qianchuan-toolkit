# 界面结构与元素定位

## 1. 入口

```
https://qianchuan.jinritemai.com/overall-prom?aavid=<账户ID>&campaignType=1&uniTab=ad&marGoal=1&uniVideoTab=1&overallPromViewTab=plan
```

- 顶部主导航 **全域投放** → 子 tab **推直播间｜推商品**。本插件只服务「推直播间」。
- 页面是 SPA，登录态在浏览器里；脚本**只连已有标签页**，不负责登录，也不自己起浏览器。
- 列表按**抖音号**成行（一个抖音号一行），一个商品可以有多行。

## 2. 列结构（左右顺序可能随版本微调）

| 列 | 内容 | 插件怎么用 |
| --- | --- | --- |
| 抖音号 | 头像 + 昵称 + 抖音号ID | 取首格首行文本作 key |
| 投放状态 | 投放中 / 已暂停 / 未有效投放 | 正则判断，暂停跳过 |
| 投放设置 | 每日预算 20000元、ROI目标 2.53(净成交) | 从行文本里正则抽，做记录 |
| 调控工具 | 一键调速、素材/人群追投、搜索抢首屏 | **点这里进调控弹窗** |
| 操作 | 编辑 / 日志 / 升级乘方 / 诊断 | 不碰 |
| 效果诊断 | 诊断建议 | 不碰 |
| 整体消耗(元) | 当日累计消耗，如 3414.90 | 只做展示；判定用分时接口 |
| 净成交ROI | 当日累计净成交ROI，如 2.57 | 只做展示，**不参与判定** |
| 净成交金额(元) | 当日累计净成交额，如 8782.39 | 只做展示；判定用分时接口 |
| 1小时内退款率 | 百分比 | 参考 |
| 整体支付ROI | 支付口径 | 不看 |

因为列顺序会变，提取脚本**先读 `thead th` 建表头索引**，再用索引取单元格；
正则匹配失败时退回整行文本 `rowText`，不会因为列位移而读到错列。

## 3. 调控弹窗

点行内「一键调速」→ 弹出标题 **调控工具** 的弹窗：

```
调控工具
┌─────────────┬─────────────┬─────────────┐
│  一键调速    │ 素材·人群追投 │  搜索抢首屏  │   ← 三张卡，当前卡高亮
└─────────────┴─────────────┴─────────────┘
调控方式   ( ) 一键起量      (•) 一键控量      ← radio
调控预算(元)  [ 请输入 ]                       ← input
调控时长      [ - ] 0.5 小时 [ + ]             ← 步进器，默认 0.5
                                  取消   提交
```

要点：

- 弹窗默认停在「一键起量」，**必须显式切到「一键控量」**，否则填的预算会被当成"起量预算"（放大消耗，正好相反）。
- 「调控时长」默认就是 0.5 小时，与规则一致时可原样保留；脚本会先尝试直接写值，写不进去就沿用步进器当前值。
- 提交后**必须**校验 toast（`提交成功` / `设置成功`）或弹窗消失，否则视为失败并保留截图。

## 4. 定位铁律（踩过的坑）

1. **输入框绝不 clickAt**。真实鼠标点输入框会触发浮层/校验/失焦重渲染，值会被吃掉。
   正确做法：`input.focus()` + 用 `HTMLInputElement.prototype.value` 的 setter 赋值 +
   派发 `input`/`change` 事件，再 `blur()`。
2. **tab、radio、行内按钮用 JS `.click()`**。这些是 React 合成事件，JS click 足够且更稳。
3. **但「一键调速」「提交」这类会打开/关闭浮层的按钮，用真实鼠标 clickAt 更可靠**，
   尤其是浮层里居中渲染的按钮——JS click 偶尔会被遮罩层吃掉。
   所以 `control.mjs` 分两段：先 eval 拿到按钮 rect 中心坐标，下一个 CDP 调用再 clickAt。
4. **弹窗打开时不要在左侧列表区域点击**（x < 300 附近是侧边栏和列表首列），会误关浮层或选中行。
5. 行匹配用**整行文本包含抖音号名**，并且强制校验**唯一命中**：
   命中 0 行 → `NO_ROW`；命中多行 → `MULTI_ROW`，一律不执行，把候选行文本打出来人工判断。
6. 不要在 URL 上手拼 `adId=` 之类的参数跳详情页，容易卡在加载态；一律从列表点进去。

## 5. 「一键控量」入口与弹窗（2026-11-18 真机确认）

- 入口在**列表页** `/uni-prom?aavid=…`（推直播间 tab），**不是详情页**。
  每行「调控工具」列 = `.interfere-tool-wrapper`，里面每个工具一个 `.assist-task` 分组，
  分组内 `.title` 是工具名（一键调速 / 素材·人群追投 / 搜索抢首屏），右侧 `iconpark-icon` 图标有三态：
  - `oc-chart-histogram` → 查看该工具的调控任务数据，**点它会跳 detail 页**，不是弹窗；
  - `oc-icon-plus` → 开启/创建，**控量弹窗就是从它打开**；
  - `iconPauseFilled` → 该工具已有任务在跑；**一键控量运行中就是这个图标**，
    hover 出 tooltip「停止一键控量」，点它弹「确定要停止控量吗？」（内含控量预算与时间窗）。
  - `iconPlay` → 搜索抢首屏已开启。
- 图标 class 含 `hover-show`，未 hover 时 `getBoundingClientRect()` 全 0（不能拿坐标点）。
  但 **JS `.click()` 直接点 plus 仍能打开弹窗**，不必先 hover。
- 详情页「调控」tab（`tb=uni_task_center`）**看不到一键控量任务**：它只列
  一键调速(一键起量) / 素材人群追投 / 搜索抢首屏 三类任务。
  控量记录只体现在列表行的 `iconPauseFilled` 与 tooltip 上，**别用任务中心验收控量**。
- 弹窗 `.ovui-modal`（标题「调控工具」）**高度随调控方式变化**：
  - 一键起量：rect `y=91 h=772`，提交按钮中心 ≈ (1392, 823)；
  - 一键控量：rect `y=165 h=624`，提交按钮中心 ≈ (1392, 749)。
  → 提交前必须**重新量** footer 里最后一个文本=「提交」的按钮，不能复用填表时的坐标，
  否则会点到弹窗空白处，表现为「点了没反应、弹窗不关、无 toast、无报错」。
- 控量模式字段：调控方式 radio（一键控量）/ 调控预算(元) input / 调控时长 input
  （0.5–24 小时，默认 0.5）/ 任务名称（**自动生成**，形如
  `20261118_看后搜一键投_直播间购买_18:14:10`，不是 `_一键控量_`）。
  底部提示「一键控量设置后需要 3～5 分钟生效，请提前设置」。
- 提交成功的判据：**没有成功 toast**，看「弹窗消失 dialogGone=true」+ 列表行出现 `iconPauseFilled`。
- 打开弹窗前必须清掉残留弹窗：`.ovui-popup__mask` 会铺满全屏（z=2000），
  此时 `elementFromPoint` 命中的是 `.ovui-modal__footer`，plus 图标拿不到 rect、hover 无效，
  表象就是「+ 图标点不动」。
